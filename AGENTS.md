# Agent guide for vFinder

## Project overview

vFinder is a desktop file manager built with React, TypeScript, Vite, Tailwind CSS, and Tauri 2. The frontend lives in `src/`; the Rust/Tauri application lives in `src-tauri/`. Linux builds use GTK 3 and WebKitGTK 4.1. The app uses a custom undecorated window and draws its own toolbar and window controls.

## Commands

- `npm install` installs frontend and Tauri CLI dependencies.
- `npm run dev` starts the Vite frontend only. For the native desktop app, use `npm run tauri dev`.
- `npm run build` runs TypeScript checking (`tsc`) and creates the production frontend in `dist/`.
- `npm run tauri build` builds distributable desktop bundles; `src-tauri/tauri.conf.json` runs `npm run build` first.
- `cargo check --manifest-path src-tauri/Cargo.toml` checks the Rust backend without producing a release bundle.

There is no test script configured in `package.json`. Linux builds need the Tauri system libraries; consult `README.md` for distro-specific runtime and build dependency lists.

## Architecture and key files

- `src/App.tsx` owns application state and orchestration: tabs, navigation/history, search, selection, keyboard shortcuts, clipboard operations, split panes, and loading directory entries.
- `src/components/Toolbar.tsx` implements the custom title bar, window controls, tab strip, view switcher, and search field. The window is undecorated, so changes to drag regions or toolbar layout can affect native window movement and controls.
- `src/components/Views.tsx` contains the icon, list, column, and gallery views. `SplitExplorerPane.tsx` hosts a second interactive explorer pane.
- `src/components/Sidebar.tsx` renders favorites, tags, and mounted volumes.
- `src/components/ModalsAndMenus.tsx` contains Quick Look and common dialogs/menus; `DownloadModals.tsx` contains download UI.
- `src/components/FileIcon.tsx` renders file icons and thumbnails.
- `src/api.ts` is the frontend boundary for Tauri commands. Keep command names and payload shapes synchronized with Rust.
- `src/types.ts` contains TypeScript models corresponding to serialized Rust models.
- `src-tauri/src/main.rs` configures Tauri, performs native window/WebKitGTK setup, and registers the command handler list.
- `src-tauri/src/commands.rs` implements filesystem, preview, metadata, volume, and other Tauri commands.
- `src-tauri/src/models.rs` defines serializable backend data structures. Models use `serde(rename_all = "camelCase")` to match frontend property names.
- `src-tauri/src/download_server.rs` runs the local HTTP server for intercepted downloads and token-scoped video/PDF preview streams. Its port may fall back to an available port if 45456 is occupied; preview URLs use the actual bound port.
- `src-tauri/src/download_manager.rs` implements download lifecycle and progress handling.

## Making changes

- Add frontend calls in `src/api.ts`, backend implementations in `src-tauri/src/commands.rs`, and register every new command in the `tauri::generate_handler!` list in `src-tauri/src/main.rs`.
- Use `spawn_blocking` for filesystem work that could block the async Tauri command runtime. Keep potentially expensive file enumeration and preview work off the UI thread.
- Preserve the camelCase serialization contract between Rust models and TypeScript interfaces.
- For large media previews, use the local tokenized HTTP stream and byte-range support instead of reading the entire file into a data URL. The WebView's media/PDF support depends on the system WebKitGTK installation.
- Keep the app's custom window usable on Linux desktops: the native window has decorations disabled, and blank toolbar areas need to remain draggable while controls continue to receive clicks.
- Keyboard shortcuts are implemented centrally in `src/App.tsx`. The established shortcut convention is Ctrl-based; avoid introducing Super/Command bindings.
- The app accepts an optional directory path as a startup argument. Relative paths are resolved against the process working directory; no valid directory argument means the app starts at Home.
- App preferences and some view settings are stored in `localStorage`; check existing keys and initialization behavior before changing defaults or persistence.
- Avoid unrelated formatting or broad refactors in this long-lived codebase. Inspect `git status` before editing and preserve pre-existing user changes.

## Build artifacts and diagnostics

- `dist/` is generated by Vite and is consumed by Tauri packaging. A frontend build rewrites files there; do not include generated `dist/` churn in source changes unless specifically requested.
- On Linux, set `VFINDER_WEBVIEW_DEBUG=1` when launching to enable WebKit console and load/process diagnostics configured in `main.rs`.
- Frontend global errors and unhandled promise rejections are logged in `src/main.tsx`.
- When reporting verification, distinguish frontend build/type-check (`npm run build`), Rust check (`cargo check`), full bundle build, and actual runtime testing.
